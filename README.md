# Сервис библиотеки
## Заданеи
Вариант №1868679

Разработать веб-приложение на языке Java с использованием Spring Boot, реализующее сервис заявок.

Предметная область: библиотека.
Основной объект системы: событие.
Пользовательская роль: менеджер.
Обязательный сценарий: оформление заказа.

Система хранения типа «ключ — значение»: Etcd.
Дополнительные параметры

- сценарий временного хранения: временная заявка;
- сценарий кэширования: настройки пользователя;
- атомарный механизм: счётчик просмотров объекта;
- исследование поведения системы: конфликт параллельных записей.

## Хранение данных
Данные разделены между двумя хранилищами:

- PostgreSQL хранит пользователей и их постоянные настройки
- Etcd хранит книги, доступность книг, счётчики просмотров, временные заявки и кэш настроек

Пользователи хранятся в PostgreSQL. В таблице users содержатся идентификатор, имя пользователя и хеш пароля

Таблица PostgreSQL:

```sql
CREATE TABLE IF NOT EXISTS Users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(60) UNIQUE NOT NULL,
  password_hash VARCHAR(60) NOT NULL
);

CREATE TABLE IF NOT EXISTS User_settings (
  username VARCHAR(60) PRIMARY KEY,
  genre VARCHAR(100) NOT NULL
);
```

Каталог книг и заявки хранятся в Etcd. Данные книги представлены JSON документом, а состояние доступности хранится отдельным значением

Ключи Etcd:
| Ключ | Формат значения | Назначение |
| --- | --- | --- |
| `/books/data/{bookId}` | JSON | Основные данные книги |
| `/books/availability/{bookId}` | `true` или `false` | Текущее состояние доступности книги |
| `/books/views/{bookId}` | целое число | Количество открытий подробной информации о книге |
| `/orders/{orderId}` | JSON | Временная заявка на получение книги |
| `/cache/user-settings/{username}` | JSON | Кэш фильтра жанра для пользователя |

1. В ключе книги хранится JSON с названием, автором, жанром и описанием
2. В ключе заявки хранится JSON с идентификатором книги

Заявка создается с Etcd Lease. Время жизни задается свойством `orders-service.order-ttl-seconds` и сейчас составляет 300 секунд. После истечения Lease ключ заявки удаляется автоматически. В текущей реализации идентификатор заявки совпадает с идентификатором книги, поэтому одновременно может существовать только одна заявка на одну книгу

## Основные сценарии

1. Просмотр каталога

Пользователь запрашивает `GET /api/v1/books`. Можно передать параметры genre и available. Сервис получает книги из Etcd, читает их доступность и возвращает только книги, соответствующие фильтрам

2. Создание временной заявки

Пользователь отправляет `POST /api/v1/orders` с идентификатором книги. Сервис создает Lease и сохраняет заявку в Etcd. Заявка существует до отмены, подтверждения или истечения времени Lease

3. Подтверждение выдачи книги

Пользователь отправляет `POST /api/v1/orders/{orderId}/confirm`. Etcd транзакция проверяет существование заявки и значение доступности книги. Если книга доступна, транзакция одновременно меняет доступность на false и удаляет заявку. Если книга уже выдана или заявка истекла, сервис возвращает конфликт

## Исследование параллельных записей

Исследование запускается командой:

```bash
make test-etcd-conflicts
```

Команда поднимает три узла Etcd и запускает `EtcdConcurrentWritesIT`

Первый тест исследует оптимистическую блокировку. Сто параллельных операций увеличивают один счётчик просмотров. Каждая запись проверяет `modRevision`, а при конфликте повторяется с актуальным значением. Ожидаемый итоговый счётчик равен 100

Второй тест исследует пессимистическую блокировку. Два клиента одновременно пытаются взять одну книгу. Каждый клиент перед чтением доступности захватывает распределённый Etcd lock. В критической секции может находиться только один клиент, поэтому книгу получает только один из них. Lease автоматически ограничивает время жизни блокировки
